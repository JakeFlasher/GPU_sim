# SM86 simulator live baseline and core-closure handoff — 2026-08-29

This directory records the current RTX 3090 Ti `sm_86` live cohort and the
corresponding release `sim-run` diagnostics. Raw traces, NCU reports, static
sidecars, and replay JSON remain in the local capture roots named in the
campaign log; this tracked summary is the portable index and claim boundary.
The complete per-cell command/status/identity record is
[`campaign_manifest.json`](campaign_manifest.json); the bounded raw evidence
is retained in [`evidence/raw_cohort.tar.zst`](evidence/raw_cohort.tar.zst).
The current-host command transcript and revision/hash binding are in
[`evidence/host.json`](evidence/host.json), with captured stdout/stderr files
under `evidence/host_preflight/`.

## Outcome

The six-cell GPU-only cohort completed separate correctness, NCU, NVBit,
static-control, and simulator stages. Every correctness run exited 0. Each
portable NVBit capture has one exact accepted launch, full block coverage, and
`total_insts == total_reported_insts`; the five portable simulator replays have
full coverage and `smsp__inst_executed.sum == sim instructions`. Every simulator
cell replayed twice to identical JSON bytes. NCU values were comparison targets
only and were not passed to `sim-run`, cards, or tuning.

The raw traces also pass the LCD layout verifier when its documented
post-processing steps are applied on a copy: `pad_dynamic_trace_pb.py` raises
the fixed manifest to 1,026 bytes and `emit_lcd_per_cta_tb_json.py` emits one
identity sentinel per CTA. Canonical traces remain sentinel-free and pass the
pinned forward-admission consumer; this keeps metadata projections from being
mistaken for protobuf payloads.

The first direct portable NVBit attempt deliberately used
`ACTIVE_FROM_START=0` and produced a successful process exit with zero accepted
launches. That artifact is invalid for this cohort. The corrected command uses
`ACTIVE_FROM_START=1` because these binaries do not emit profiler start/stop
markers; the async research probe remains profiler-marked and uses 0.

Correctness is a separate base-binary lane. All six correctness captures were
rerun with a minimal CUDA runtime environment and the profiler/injection
variables explicitly absent; the effective argv/environment records are kept
next to each stdout/stderr pair. The clean async correctness run and its
retained 16,384-group NCU result are a separate scaling observation. The
matched cohort uses the same 64-group trace binary and `c11 l1 0 4 1`
arguments for NCU, NVBit, static-control, and simulator replay.

The active replay validator now derives trace instruction/sector invariants and
records per-launch readiness, modeled-event, completion-frontier, and typed-tail
diagnostics. The compact summary is
[`semantic_replay_summary.json`](semantic_replay_summary.json); the complete
per-launch report is the compressed
`semantic_replay_report.json.zst` referenced there.

Each NVBit root also has a `campaign_binding.json` sidecar. It binds the
traced-binary hash, injection path, trace output root, dynamic protobuf, stats,
mapping, enhanced execution metadata, and launch geometry; the fresh validator
checks those bindings before passing a replay to `sim-run`.

The same semantic checks are applied independently to the six fresh live
replays by `workloads/research_probes/validate_sm86_live_cohort.py`; its
per-cell report is `live_cohort_semantic_report.json`. Every recorded stage has
a finite watchdog (correctness 180 s, NCU 900 s, NVBit 900 s, static control
300 s, simulator 900 s; retained-corpus validation 1,800 s). NVBit captures
are launched through `capture_sm86_nvbit.py` with an exact `env -i` allowlist;
each root retains a hashed effective-environment record.

The residual decision is generated by
`workloads/research_probes/analyze_sm86_live_closure.py`. It compares the
canonical NCU capture with the independent
`evidence/raw/ncu_repeat/rep-2/` capture, checks byte-identical simulator
twins, preserves typed readiness/frontier causes, and writes
[`closure_report.json`](closure_report.json). This report is a diagnostic
selection record. Its SM-completion, GPC-completion, and GPC-launch-envelope
dimensions remain independent; the next discriminator is selected by an
explicit mechanism-local typed-tail rule rather than by summing independent
frontiers into a cross-frontier scalar. NCU measurements never become
simulator inputs.

## Reproduction commands

The release simulator build is a separately recorded, campaign-bound step:
`evidence/host_preflight/release_build.json` contains the exact command,
finite timeout, exit status, revision, transcript hashes, and resulting
`sim/target/release/sim-run` hash. The cohort validator checks this record
against the current binary before accepting any replay.

Correctness (one per portable cell):

```bash
workloads/portable_lcd/<slug>/<slug>_run \
  --correctness_shape --seed 42 --warmup 1 --reps 1 --output_dir <out>
```

NCU is a separate application-replay process (no simulator input):

```bash
.venv/bin/python tools/local_labels/collect_ncu.py \
  --ncu /usr/local/cuda-13.2/nsight-compute-2026.1.0/ncu \
  --timeout 900 \
  --output <ncu-out> \
  --metrics gpc__cycles_elapsed.max,sm__cycles_active.max,\
smsp__inst_executed.sum,lts__t_sectors_srcunit_tex_op_read.sum,\
dram__sectors_read.sum,sm__pipe_tensor_cycles_active.sum \
  --launch-skip 1 --launch-count 1 --replay-mode application \
  --clock-control none -- \
  workloads/portable_lcd/<slug>/<slug>_run --timing_shape --warmup 1 --reps 1
```

## Residual and closure decision

The portable simulator issue, last-modeled-event, and completion-frontier
values are typed lower bounds, not cycle predictions. Complete frontiers retain
an exact completion cycle; incomplete frontiers retain only a lower bound and
their typed retirement-tail flags. The closure report keeps separate SM-active
and GPC-elapsed gaps for each frontier; its multi-frontier selection vector is
the SM-completion gap, GPC-completion gap, and measured GPC launch-envelope gap.
The six comparable rows trail NCU
`sm__cycles_active.max` by 2,770 / 2,624 / 3,867 / 1,650 / 1,928 cycles at
the completion lower bound for BF16, FP16, INT8, sparse BF16, and attention.
All five expose `dirty_writeback=true` and `coherence=true` in
`incomplete_unmodeled_retirement_tails`.

This is a reproducible **no-go** for a timing scalar patch in this round. A
fixed latency, per-workload offset, or NCU-derived card value would conflate
unmodeled retirement/coherence with async/barrier overlap and violate the
simulator's evidence boundary. The next discriminator is a matched
store-free/barrier-free async-source pair with an independent retirement
observable. Its exact prospective source, 40-cell matrix, commands, output
paths, and pass/falsify/unknown rules are pinned in
[`plans/sm86_ldgsts_burst_release_next_discriminator.json`](../../../plans/sm86_ldgsts_burst_release_next_discriminator.json).
The manifest is explicitly `prospective_not_run`; no simulator timing code, JADE/HETR code, CPU-GPU bridge,
`sm_120` behavior, or rejected candidate was changed here.
The machine-readable frontier table, explicit AC-1 through AC-5 status, and
repeatability evidence are in
[`closure_report.json`](closure_report.json).

## Freshness refresh

The initial active-pair validator found 5,519 retained JSON outputs older than
their current checkout inputs. This was timestamp staleness, not a semantic
replay failure: one launch-cycle pair was regenerated immediately and passed
the identity helper. The release simulator then regenerated the launch,
retirement, arrival, admission, service-candidate, admission-candidate, and
feedback/sweep matrices with deterministic twin checks. The final validator
reports `5,519` fresh, schema-matched, byte-identical active pairs. It also
sees `2,070` known supplemental candidate directories produced by the full
exploratory sweep; those are classified separately rather than deleted or
treated as a workflow failure. The validator also recomputes the content-bound
aggregate in [`evidence/sm86_active_replay_binding.json`](../../../evidence/sm86_active_replay_binding.json),
so freshness cannot be manufactured by changing timestamps alone.

## Claim limits

The cohort demonstrates a working, deterministic `sm_86` trace-to-replay path
and exposes the remaining causal frontier. It does not claim cycle accuracy,
cross-architecture support, or complete writeback/coherence modeling. The
portable NVBit manifest is intentionally small; payload bytes live in the
per-CTA protobuf files. The LCD sentinel projection must be validated on a
copy, because adding `tb_*.json` sentinels to a canonical trace makes the
forward admission consumer reject the tree as non-payload input.
