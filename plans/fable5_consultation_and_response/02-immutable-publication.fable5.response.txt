Consolidated advisory ruling for FABLE5-CONSULTATION-V1 (immutable artifact publication, retention, race, and durability). All rulings are decided solely from the embedded evidence; nothing below authorizes mutation, capture, commit, or handoff.

Q601: AMEND

**Rationale.** E605 already implements the pinned-chain reader, but B601's literal demand (full seven-field snapshots on *every* ancestor) over-constrains live parents whose mtime/ctime legitimately change with unrelated sibling activity, while the leaf demand is exactly right. The correct contract distinguishes leaf snapshots (full) from ancestor bindings (identity + type + name, continuously reverified), and full ancestor snapshots apply only inside frozen trees (E609 `_PinnedTreeTransaction`, E605 verify paths).

**Replacement state machine.** States: S0 CLOSED → S1 CHAIN_PINNED → S2 LEAF_PINNED → S3 CONSUMED → S4 REVERIFIED → S0. Transitions: S1 opens "/" then each component with `O_RDONLY|O_DIRECTORY|O_CLOEXEC|O_NOFOLLOW` via `dir_fd` (≤ 64 components, ≤ 4096 path bytes), then verifies the chain: for each (parent, child, name), `os.stat(name, dir_fd=parent, follow_symlinks=False)` must be a non-symlink directory whose (st_dev, st_ino, S_IFMT) equals `fstat(child)`. S2 stats the leaf no-follow (regular, st_nlink == 1), opens it `O_RDONLY|O_NOFOLLOW|O_CLOEXEC|O_NONBLOCK` via `dir_fd`, and re-verifies chain plus leaf name binding (both regular, nlink == 1, identical node identity). S3 consumes exactly `st_size` bytes on the pinned descriptor, probes one extra read for EOF, and requires seven-field equality (dev, ino, mode, nlink, size, mtime_ns, ctime_ns) between the before/after `fstat`. S4 repeats chain and leaf verification on the retained descriptors. Any exception in any state closes all owned descriptors in reverse order before propagating; close errors are swallowed only during unwind.

**Invariants.** I1: no traversal step follows symlinks. I2: leaf st_nlink == 1 at declare, open, and every reverification. I3: the seven-field leaf snapshot is byte-stable across consumption. I4: ancestors bind name→(dev, ino, fmt) identity only; full ancestor metadata snapshots are required only inside frozen published/retained trees. I5: all content reads occur on the originally pinned descriptor; a second path traversal never substitutes for descriptor identity.

**Failure codes** (existing typed ImmutableArtifactError texts retained): "named directory component chain changed", "named regular-file path changed", "hard-linked regular file is not immutable", "regular file changed during snapshot read", "regular file truncated during snapshot read".

**Order.** (1) Codify the state table in `tools/local_labels/immutable_artifact.py` docstrings; (2) add direct tests in `tools/local_labels/test_m5_calibration_controller.py`.

**Tests.** Positive: 64-deep chain read returns bytes with descriptor count returning to baseline; `PinnedDirectoryReader.read` reverifies root before and after. Negative: replace an ancestor directory with a same-named new directory mid-read; swap the leaf inode for identical bytes between S3 and S4; create a second hardlink during the read; truncate/append during the read; symlinked ancestor (retain E607's anchored-snapshot cases and E606's symlink/hardlink rejections).

Q602: AMEND

**Rationale.** E605's installer never unlinks after failure and even preserves a racer's replacement, with an explicit comment that unlink-by-name after any identity check is a TOCTOU. E609's `_write_new` unlinks an owned incomplete partial after snapshot equality, and E607 asserts that deletion in the zero-write test. The two are in direct conflict; the E605 rule is controlling because fstatat-then-unlinkat is inherently racy against a same-UID writer, and B602 forbids pathname unlink of incomplete partials.

**Replacement algorithm (all producers).** (1) Preflight: destination and partial both absent; create partial `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC`; `flock LOCK_EX|LOCK_NB`; fsync parent. Allowed: none in producer failure or recovery paths. The only name removal is the `RENAME_NOREPLACE` of a verified exact-complete, locked, snapshot-pinned partial into its final name. Quarantine or deletion of preserved partials is an operator-only action outside these producers.

**Case table.** Zero/short write → typed `M6_OUTPUT_WRITE` / "short immutable-artifact write", partial preserved (M6 zero-write test updated: `.zero.json.m6-partial` must exist). Copy exception → typed, partial preserved (E605 already conforms). Foreign replacement → `M6_OUTPUT_REPLACED` / "locked deterministic partial path changed", both inodes preserved (retain E607's replacement case verbatim). Process crash → partial persists, lock auto-released; restart: E605 path adopts only an exact-complete partial (hash + size + read-only + nlink == 1 + lock acquired) and preserves incomplete ones typed ("incomplete pre-existing partial is preserved"); `_write_new` restart refuses typed `M6_PARTIAL_PRESERVED` and never auto-deletes.

Q605: AMEND

**Rationale.** E605's own comment concedes one retained descriptor per file; E614 (307,210 retained files), E618/E622 (5,033 payloads; 1,135-file snapshot) prove that per-path retention exceeds ordinary RLIMIT_NOFILE. 

**Contract.** Verification gains two modes with identical detection semantics. Pinned mode (N ≤ 512 files): current double-hash, per-file retained descriptors, unchanged. Snapshot-closure mode (N > 512; mandatory for the 5,033-payload and 307,210-file authorities): never more than O(depth) descriptors. Algorithm: single pinned root; iterative traversal with an explicit stack, reopening chains descriptor-relatively; inventory pass records the seven-field snapshot per entry; hash pass opens each file, verifies name binding, hashes exactly once with before/after fstat equality, records the snapshot, closes; closure pass re-inventories (set equality) then re-opens each named file and directory, fstats, and requires seven-field snapshot equality, then closes.

**Race argument.** Any mutation or replacement strictly changes (st_dev, st_ino) or increases st_ctime_ns; an unprivileged same-UID writer cannot set ctime backwards, and a recycled inode created after the first hash carries a later ctime. Snapshot equality at closure therefore proves the hashed inode is the unmodified named inode — the same guarantee the retained descriptor gave, without the descriptor.

**Bounds.** Simultaneous descriptors ≤ 64 (chain) + 2; each byte hashed exactly once (twice only in pinned mode); O(N·depth) stats, O(N) opens; memory O(N) fixed-size snapshots (≈ 17 MiB at 307,210 files); no recursion; all opens in try/finally (no leak on failure). Startup guard: RLIMIT_NOFILE ≥ 96 or typed `VERIFY_RESOURCE_BOUND`.

**Tests.** Positive: synthetic ≥ 20,000-file tree verified under `resource.setrlimit(RLIMIT_NOFILE, 256)` with a peak-descriptor audit ≤ 96 and a hash-call counter proving single hashing. Negative (adversarial): replace-after-hash with identical bytes detected at closure via inode/ctime; mutate-and-restore via `os.utime` detected via ctime; injected exception mid-walk with descriptor count returning to baseline; depth-65 path rejected; existing E606 nested-inode replacement test retained.

Q611: ACCEPT

**Threat and trust boundary.** `flock` advisory locks bind only cooperating processes that open the same inode and request the lock: they serialize concurrent cooperating publishers (equal or different payloads) and nothing else; they are defeated by any same-UID process that ignores flock, and by replacement of the locked name. Modes 0444/0555 are point-in-time discretionary attributes: a same-UID owner of a writable parent can chmod, replace, or unlink regardless. Both are therefore tamper-evidence levers, not prevention: chmod/replace/mutation moves ctime or changes inode identity, which the pinned-descriptor seven-field snapshots and `RENAME_NOREPLACE` commit detect. The enforceable boundary is detection-then-typed-failure; durable *prevention* against a same-UID writable-parent owner would require a distinct UID or privileged immutability flags (operator-only, out of scope).
