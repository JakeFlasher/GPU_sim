# SM86 asynchronous-copy cohort reservation-exposure milestone

## Context and current evidence

The schema-17 cohort source-response milestone is complete and accepted by
Humanize RLCR at commit `95364244`. It retains exact source-sector/cohort
membership and first/last modeled response times without changing production
timing. Its matched-pair probe holds each copy's source address vector and
destination address multiset fixed while swapping whether cold source cohorts
receive compact or severe destinations.

The v2 direct evidence contains eight depth/spacing comparisons and nine paired
AB/BA repeats per comparison. Every median issue delta is zero and every
`slow_expensive - slow_cheap` wait delta is negative, from -5.460 to -17.694
cycles/group. The schema-17 post-response candidate predicts +15.750 for every
comparison. That sign disagreement was not admitted as causal because six of
eight independently launched NCU pairs exceeded a frozen tolerance on
`dram__sectors_read.sum`.

That gate asked a device-wide counter to prove a source-local property.
NVIDIA's Nsight Compute profiling guide states that display, copy, and video
engines share L2/DRAM and that SM DRAM traffic cannot be isolated when such
activity overlaps. This GA102 is display-active, and it exposes no
source-qualified `dram__*` counter. It does expose local-device-aperture LTS
hit/miss sectors explicitly attributed to the L1TEX source unit. Bounded local
diagnostics also establish that application replay can profile both variants
back-to-back as two ordered rows while raw DRAM remains noisy and the
L1TEX-attributed LTS marginals remain bounded.

The reverse live sign cannot be generated by an independent monotone
post-response destination tail under matched source and topology marginals.
The smallest remaining observation is therefore a partial-order score for
destination reservation/preparation hidden by the copy response envelope. It
is not a new completion frontier and cannot authorize production timing in this
milestone.

## Goal

Replace the invalid raw-DRAM equality gate with a fresh, same-application,
source-attributed paired NCU campaign; add a timing-neutral schema-18
first-response-anchored topology-reservation exposure score; and evaluate its
fixed identification/holdout transfer on the retained live pairings. Finish
with either a bounded observational match or a completed no-go while leaving
bypass wait readiness and `async_copy_shared_visibility` unchanged.

## Non-goals

- No claim of per-kernel physical DRAM service equality on this display-active
  host.
- No change to the CUDA probe binary, source layout, prewarm, markers, direct
  timing corpus, or NVBit traces.
- No new fitted coefficient, Q sweep, per-layout constant, intercept, scale,
  or correction from live timing.
- No activation of schema-18 data in scheduler/wait readiness and no typed-tail
  removal, even if the score transfers.
- No JADE/HETR, CPU-GPU co-simulation, `sm_120`, CUPTI profiler integration, or
  headless-display reconfiguration.
- No cryptographic approval gate. Ordinary content identities may be recorded
  for reproducibility but do not authorize conclusions.

## Interfaces and compatibility

### Source-attributed paired NCU evidence

Reuse the exact v2 probe binary and run both target variants in one application
invocation. Profile exactly two selected launches in their execution order with:

```text
--devices 0
--target-processes application-only
--profile-from-start off
--launch-count 2
--replay-mode application
--app-replay-mode strict
--app-replay-match grid
--cache-control none
--clock-control none
```

Each paired observation is a bundle of four focused one-metric profiles:

```text
smsp__inst_executed_op_ldgsts.sum
lts__t_sectors_srcunit_tex_aperture_device_op_read_lookup_hit.sum
lts__t_sectors_srcunit_tex_aperture_device_op_read_lookup_miss.sum
dram__sectors_read.sum
```

`dram__sectors_read.sum` is retained as a non-gating device-background
sentinel. The attribution frontier is the L1TEX-source, local-device-aperture
LTS request stream. The reducer must label it requested L2-hit/L2-miss demand,
not physical DRAM completions.

The metric families are deliberately separate: a bounded pre-plan smoke proved
that requesting the LTS family together requires four replay passes, while
each listed metric alone requires exactly one. Combining them would make the
cache state pass-history-dependent under `--cache-control none`.

For every depth `1/2/4/8` and spacing `0/4`, retain ten paired NCU bundles:
odd repetitions use AB order and even repetitions use BA order. Each report
inside a bundle uses 64 groups and must contain exactly two target rows with
IDs 0 and 1. The row-to-variant map comes only from the recorded invocation
order. This yields 80 bundles and 320 one-pass reports. NCU timing is not a
live timing label.

The timing-blind admission gates are:

- exact v2 probe binary identity, arguments, kernel/grid/block, LDGSTS count,
  source address/32-byte-sector multiset, and destination topology multiset;
- per row, LDGSTS instructions = `64 * depth`;
- per row, device-aperture LTS hit + miss sectors = `64 * depth * 32`, with
  both separately collected populations nonzero;
- per paired repeat, absolute hit and miss deltas are no greater than
  `max(4, ceil(0.01 * 64 * depth * 32))`; and
- every selected row in every profile reports one replay pass.

Record raw DRAM, `raw_dram - attributed_lts_misses`, clocks, order, and all
rows, but never use them to override attributable LTS admission.

### Schema-18 reservation-exposure observation

Reuse the schema-17 cohort response state. For each copy `i`, define the
earliest first response:

```text
A_i = min_c(first_response_i,c)
P_i,c = 4 * (bypass_wavefronts_i,c - 1)
      + 2 * (bank_wavefronts_i,c - 1)

prearrival_hidden_i,c = min(P_i,c, first_response_i,c - A_i)
stream_hidden_i,c = min(
    P_i,c - prearrival_hidden_i,c,
    last_response_i,c - first_response_i,c
)
residual_i,c = P_i,c - prearrival_hidden_i,c - stream_hidden_i,c

copy_residual_i = max_c(residual_i,c)
group_residual_g = max_i(copy_residual_i)
```

The paired prediction is only:

```text
(sum(group_residual_slow_expensive)
 - sum(group_residual_slow_cheap)) / groups
```

This is a first-response-anchored topology-reservation exposure hypothesis.
Only routing, arbitration, reservation, or other preparable work could satisfy
it; it is not evidence that bank writes happen before data arrives.

Add checked, additive diagnostics:

```text
cohort_overlap_groups_observed
cohort_response_envelope_cycles
cohort_topology_prearrival_hidden_cycles
cohort_topology_stream_hidden_cycles
cohort_topology_residual_exposure_cycles
```

Schema 18 is selected by the observed-group count even when residual exposure
is zero. Do not modify `AsyncCopyGroup::completion_time`, destination service,
`async_wait_clear_time`, wait consumption, traffic, cards, scheduler state, or
tail selection.

## Risks and rollback

- Raw DRAM remains contaminated by asynchronous device engines; it must stay
  visible but non-gating on this host.
- Application replay requires deterministic launch order. Two same-name/grid
  launches are distinguished by recorded execution order; a row count/order
  mismatch invalidates the report.
- The reservation score permits pre-response preparation and is not a causal
  completion model. A numerical match cannot activate timing.
- Each current cohort occupies one L2 line, so within-cohort stream hiding is
  structurally zero. A future stream-overlap assay requires a different source
  geometry and fresh traces.
- Rollback is schema 17 at commit `95364244`. No destructive data operation or
  unrelated branch change is in scope.
