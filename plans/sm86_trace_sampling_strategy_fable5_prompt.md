You are a GPU performance-measurement and simulation systems expert. Design the **detailed, implementable trace-sampling strategy** for budget-breaching cells in an sm_86 (RTX 3090 Ti, GA102) NVBit trace-capture campaign. I want a concrete design I can implement, not a survey. Be critical and flag anything that silently corrupts correctness.

## System context (these constraints make naive sampling unsound)

- We capture **NVBit dynamic traces**: per-threadblock protobuf dumps of SASS instructions + **per-lane memory addresses**. These traces are the **INPUT to an event-driven GPU simulator** (Rust) that replays them to PREDICT Nsight Compute (NCU) metric vectors (L1/L2 sector-hit rates, sector/traffic counts, cycles).
- The simulator replays **each threadblock on its traced `sm_id`** and **each warp on its physical `warpid_sm` slot** — *traced placement IS the placement model*. It joins static SASS **control-bits by `(function, pc)`**, drives a sectored **L1 (finite-MSHR) + shared sliced-L2 + DRAM** model, and enforces the invariant **`issued == records_seen`** (it issues exactly the records present in the trace). Consequently a **block subset is a DIFFERENT execution**, not "the same replay, smaller" — unless the simulator is given an explicit weighting/extrapolation mode.
- **NCU labels are captured SEPARATELY** by `ncu` on the **full timing shape** of the kernel. So there is a hard consistency requirement: whatever the sim replays must be comparable to a **full-shape** NCU label. If we sample the trace (fewer blocks / fewer records), the sim sees a partial execution and must still predict the FULL-shape metric — OR we must also capture the label at the matched reduced shape (which then no longer predicts the full-shape label).
- Traces must stay **contract-valid**: memory instructions carry data-width + op-class + positional per-lane masks; block ids present/range-checked; the reader reconstructs lane vectors. The contract validates fields/masks/widths/lane-vectors/block-identity — it does NOT require "every launched block is present" — so a subset of intact block `.pb` files is still contract-valid but is not semantically full-shape.
- Pathological sizes today: an atomic-histogram cell = **411M records / 3.5 GB** (256 blocks × ~14 MB); a DRAM-streaming cell = **78M records / 0.9 GB**. A pending tracer change will START emitting atomic + async-copy (cp.async/LDGSTS) addresses that are currently dropped, INFLATING atomic/streaming cells further. Full roster ≈ 229–250 cells; unsampled could be hundreds of GB (443 GB free).
- **Honesty rule**: any sampling must be TYPED and provenance-stamped (which cells, method, fraction, seed, strata), never silent; the sim must refuse to score a sampled trace as an ordinary full-shape prediction unless a caller explicitly opts into a sampled-estimator mode.

## The vetted ladder (an independent expert review already recommended this order — refine or challenge it)

1. **Lossless compression + retention tiers FIRST** (zstd the raw `.pb` trees; keep hashes + manifests in git; move raw/compressed blobs to cold storage). This is the only tier that preserves the exact sim contract. Sample only when compression still breaches the byte/wall-time budget.
2. **Whole-threadblock stratified-subset sampling** as a **typed experimental estimator** (NOT ordinary replay): stratify by `sm_id`, launch index, boundary/interior class, and phase/classifier statistics; force-include rare strata (boundary/epilogue/reduction blocks); require per-SM block-count homogeneity for weighting; the sim emits `sampled_input=true` and produces **estimator outputs with CIs/error bars**, not exact counters. Known to break for boundary tiles, reductions, atomics/histograms, persistent kernels, epilogues, cold-start/warmup, and kernels where a few blocks dominate L2/DRAM pressure.
3. **Matched reduced-shape trace+label** as a separate `shape_scope=reduced_representative` stratum (trace + NCU label describe the same smaller launch) — internally consistent but changes occupancy / L2 residency / DRAM pressure / atomic contention / SOL saturation, so it is "reduced-shape evidence," not a full-shape label prediction.
4. **Temporal/window sampling** only for **proven-stationary** kernels (e.g. reuse an MRC-convergence ledger: K=3 windows, ≤0.02 max MRC-quantile delta) — admissible for cache-rate summaries, not general per-block SM/L2 replay unless the window is replayed with an explicit warm-state + extrapolation protocol.
5. **Typed `unavailable`** if nothing converges within budget — never silently corrupt the full-shape comparison.
- Per-record reservoir sampling is **INADMISSIBLE** (destroys ordered per-pc replay, control-bit join, barrier/dependency semantics, L1-MSHR state, shared-L2 order, and `issued == records_seen`).

## What I need from you (be concrete and implementable)

3. **Full-shape estimator + weighting.** Precisely how does the simulator reconstruct a FULL-shape metric (sector-hit rate, sector/traffic counts, cycles) from a weighted block subset? 4. **Sample-size / convergence rule.** A concrete stopping rule: e.g. per-stratum bootstrap CI half-width ≤ 0.02 absolute on sector-hit/L2-demand/record-count, plus ≥1 occupancy wave per active SM; how to pilot it cheaply; and the fallback to `unavailable`.
