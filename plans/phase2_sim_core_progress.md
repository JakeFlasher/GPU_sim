Running log for Phase 2 (design §6, build order = design-note phases A→E).

### Deferred-item closure (same night): streaming access API

The per-record `Vec<AddressAccess>` allocation is retired.
`visit_memory_access(inst, record, sink)` is the new zero-per-record-
allocation core (sink borrows a stack-resident `AddressAccess`, now `Copy`);
`memory_access()` survives as an allocating convenience wrapper implemented
ON the core (an agreement test pins the two forms together), so the
contract cannot drift between forms. The smoke exercises the streaming form
(17/17 traces re-proven).

Measured on ac4_dram_streaming_dot_product (8.49 M memory records, 27.2 M
instructions, warm page cache, release):
prost-decode-only baseline 3.19 s · allocating walk 3.81 s · streaming walk
3.49 s → the access layer's own cost halves (620 ms → 296 ms; ≈38 ns/record
= the eliminated malloc/free pair). Honest framing: end-to-end the walk
gains only ~8.5% because **prost message-tree decode dominates** (3.19 s of
3.49 s) — the next real throughput frontier is decode (arena/lazy decode or
a flat wire walk), NOT further access-layer tuning; revisit only if the SM
model's replay loop shows the walk on the critical path.

## SM issue model v0 (2026-07-06, same night) — first target metric EXACT

The §6.2 increment landed: per-warp program replay joining the dynamic
trace with the Phase-1E control bits by (function, pc), issued on a
4-sub-core CGGTY model. **`smsp__inst_executed.sum` is EXACT (bit-identical
to NCU) on 15/15 admitted M1 cells** — the deterministic-class gate for the
first target metric is met. All 17/17 traces join and replay clean.

### The join, empirically pinned before any code
- Key chain: dynamic record `function_unique_id` → exec-info
  (`extra_info/enhanced_execution_info.json`) `unique_function_id` →
  `kernel_name` minus its trailing `___<digits>` instance suffix → the
  sidecar's function key. Verified BYTE-EXACT on all 17 cells, including
  conv2d's 1.9 kB mangled CUTLASS name; static pc sets are EQUAL between
  exec info and sidecar on all 17; dynamic pcs are function-relative
  members (`vpc − pc` = constant function base).
- **Negative finding that shaped the design**: the exec info's embedded
  per-instruction `control_bits` are garbage — only 88/5,736 static
  instructions agree with the bit-validated sidecar (stall counts ~all 0,
  yield never set; NVBit records `encoded_instruction: []`, it never saw
  the raw words). The loader deliberately does NOT parse them (module doc
  records why); the Phase-1E sidecar is the sole control-bits source.
  NVBit's `op_code` is likewise skipped (its normalization disagrees with
  nvdisasm heads, e.g. "MOV" vs "IMAD.MOV.U32") — opcode classification
  comes from the sidecar's `opcode_text`.

### What landed
- `sim-trace exec_info.rs`: minimal typed loader (names, arch version, pc
  table only); hex↔dec pc transcription guard; duplicate id/pc rejection.
  `reader.rs` refactor: `block_launch_index` extracted so the replay
  driver can stream blocks without loading whole kernels.
- `sim-sm program.rs`: the (function, pc) join. Fail-closed on arch
  mismatch, missing function, and pc-set inequality in BOTH directions
  (pc only in exec info = stale sidecar; pc only in sidecar = truncated
  exec info).
- `sim-sm issue.rs`: 4 SMSPs; CGGTY pick (greedy hold while ready, yield
  drops the hold, else youngest-ready by arrival stamp); per-issue
  eligibility `t + max(stall, 1)`; 6 dependence barriers — write barriers
  clear at a per-class latency (global→card DRAM 423, shared→card 23,
  cold-cache v0), read barriers + non-memory producers behind documented
  hypothesis knobs (8 / 25 cycles); `BAR.*` = block-wide generation
  barrier (finished warps never block release — Volta+ semantics);
  resident-warp ceiling 48/SM (vendor occupancy tables; knob until the
  cards grow an occupancy block); skip-ahead when no warp is ready; typed
  `NoProgress` deadlock defense. Event-queue integration deliberately
  deferred: with no memory hierarchy yet, SMs are independent and a
  per-SM loop is the whole schedule (sim-engine hooks in with sim-mem).
- `sim-sm replay.rs`: traced placement IS the placement model — blocks
  run on their traced `sm_id` (per-block consistency asserted), warps on
  their physical `warpid_sm` slot (sub-core = slot % 4). Blocks decode
  one at a time into compact 8-byte `ReplayInst`s (pc + memory class);
  the prost tree drops before the next block loads. v0 rejects
  multi-function launches typed (none of the 17 traces has one).
  Invariant: issued == records, checked, plus exactness re-asserted in
  the smoke.

### What landed
- `sim-mem l1.rs`: lockstep port of `l1_warp_pool_walker._access_once` /

  two in-flight fill kinds under one finite MSHR pool (line merges by
  line, sector merges by (line, sector), other resident sectors still

### Finding: the Phase-1 cache-op classifier mixes fatbin arch slices
The existing per-cell manifests
(`data/local_labels/cache_op_classifier_manifests/sm_86/*`) do NOT pair
with the traced binaries: the layernorm manifest tags 12 "LDG.E" pcs of
which only 4 are LDG instructions in the traced sm_86 SASS (pc 0x140 is
ISETP, 0x9a0 is the STG, two pcs appear twice). Regenerating from the
SHA-verified traced binaries reproduces the drift → the root cause is in
`l1_cache_op_classifier._extract_kernel_section`, which concatenates the
kernel's SASS across EVERY fatbin arch slice (these `*_sm80`-named
binaries carry sm_80 + sm_86 slices). The Phase-1E control-bits
extractor handles arch sections correctly (`skipped_arch_sections`), so
the sim classifies from the sidecar's opcode text instead and consumes
no classifier manifests at all. Consequence to track OUTSIDE sim/: the
Phase-1 label-side L1 predictor consumed these contaminated manifests
(the NCU labels themselves are unaffected); the classifier fix +
downstream re-run belongs to the label-pipeline backlog.

## Review-gate 2 addendum (2026-07-06, same night — RLCR pass over 5491a487 + 69199c40)

An 8-angle finder review + KB audit + web/primary-source verification +
two new Python↔Rust differentials ran over the issue-model and L1
commits. Fixes landed (the sections above describe the code as first
written; this addendum is authoritative where they differ):

- **Dependence barriers are COUNTERS, not scalars** (primary source: the
  CGGTY paper — producer increments at issue, decrements at write-back).
  The v0 `barrier_clear` stamp was last-write-wins, so a later FAST
  producer (L1 hit, 34 cy) on the same index could shorten a pending
  slow one's (miss, 244 cy) wait — live exactly once L1 mixed latencies.
  Fixed: max-accumulate on both write and read barrier stamps.
- **Yield semantics corrected to the paper's measurement**: the yield
  bit means "do not issue this warp NEXT cycle" (a one-cycle bubble when
  no other warp is ready), not merely "drop the greedy hold". Fixed
  (eligible floored at t+2 on yield).
- **CGGTY confirmed from the paper text** (arXiv 2503.20481): "Compiler
  Guided Greedy Then Youngest" — greedy while eligible, switch to the
  YOUNGEST eligible warp; warp→sub-core = warp ID % 4 (both as
  implemented). Caveat recorded: the paper confirmed the policy for
  warps within one CTA only.
- **Two cache-op classification port divergences** (found by the
  lockstep finder, then pinned by a 5,114-line all-sidecar differential
  which passes post-fix): (1) modifier matching is now
  adjacency-contiguous like the Python regex literals (`LDG.E.128.CG` →
  bare-CA fall-through, not `.cg`); (2) `TLD4`/`TLDS` heads are not
  load-like (the Python gate `\bTLD\b` never matches them) — they are
  the silently-skipped set, not TEX.
- **classify_flat contract parity**: the no-L1 path now rejects
  addresses-without-op-class and UNSPECIFIED op_class with the reader's
  own typed diagnoses (it previously passed the former silently and
  called the latter schema skew); an owner-runner flat-mode replay of
  one real cell keeps the ablation path machine-tested.
- **Fail-closed placement completed**: a warp with records but no
  `warpid_sm` is now a typed error (was a silent `warp_id` fallback);
  wire-invalid dependence-barrier index 6 now fails `ControlBits::decode`
  closed; an all-empty-warps block no longer leaks residency slots.
- **Single latency source**: `L1Config` is now derived from
  `IssueModelParams` (`params.l1_config(...)`) — the hit/miss pair can
  no longer drift between the arch card and the pchase card consumers.
  The knob constructor is arch-tagged (`v0_sm86_from_card_latencies`)
  per the architecture-coupling rule; carding the 25/8/48 hypothesis
  knobs stays on the backlog.
- **New multi-surface lockstep test**
  `tools/cache_predictor/test_cache_op_rust_parity.py` (BL-20260507
  pattern): pins the Rust 12-token vocabulary, eligibility partition and
  bare-`LDG.E` arch set to the Python constants, plus a behavioral
  corpus through the canonical classifier.
- **Perf (finder-verified quadratic scans)**: retired warps are pruned
  from sub-core pick lists (swap-remove), skip-ahead scans resident
  warps only, block-barrier release scans the block's contiguous warp
  range, and `apply_fills` early-outs on a cached earliest-due bound.
- **Differential proofs**: the L1 cache core is bit-identical to the
  Python walker on 20 single-warp streams (hits/misses/evictions/
  two-layer split) AND 12 multi-warp pool-mode overlap runs (merges,
  in-flight fills, cap-1 eviction/drop races) — 32/32 counter-exact.
  Scope note: pool-mode equivalence is exact only in no-stall regimes;

- **Deliberate divergences documented** (Rust right, Python defects →
  label-pipeline backlog): `l1_production_helper` joins manifests by
  vpc (function-relative pcs never match a nonzero base) and applies the
  first nonzero record width to ALL lanes; the classifier's

## Shared-L2 + DRAM ladder v0 (2026-07-06, same night) — the request/response inversion

The §6.3 increment, built exactly on the gate-2 altitude notes: the
inversion FIRST, classification into sim-mem, no constant-latency L2.

### What landed

- **`sim/mem/src/l2.rs` — shared L2 model**: lockstep port of the
  sectored set-associative cache core in
  `tools/cache_replay/sector_cache_replay.py` (`replay_access_stream` +
  `_install_way`): sector-valid-bit hit rule, sector-fill vs line miss,
  LRU + SRRIP (2-bit RRPV with aging) + deterministic BIP (1-in-32),
  all six slice-hash candidates bit-exactly (overflow-free modular
  forms; pinned-value tests regenerated from the Python registry), the
  Python set mapping `slice = hash(line)`, `set = (line // slices) %
  sets_per_slice`, and the `max(1, ·)` geometry derivations.

  Python on LCG streams across {3 policies × 6 hashes} plus geometry
  corners (assoc-1 pure conflict, 7 slices, degenerate capacity,
  reuse-heavy streams). Timeless by design — the event queue supplies
  the ordering the flat Phase-1 replay approximated with trace order.
- **Rule 1 boundary made explicit** (module doc): the Phase-1 L2

## sim-emit contract layer — typed NCU-metric emission + the LDGSTS/op_ld ground-truth adjudication (2026-07-08)

Landed the `sim-emit` crate: a typed emission layer that maps summed

accounting OUT of the cache models (gate-2 altitude note c, now DONE).

- **Design (proposal P3, descriptor-table hybrid).** A compiled
  `DESCRIPTORS: &[MetricDescriptor]` is the single source of truth —
  one row binds a registry key + NCU metric string + `Unit` +

## sm_86 non-bulk asynchronous-copy completion (2026-08-14)

Implemented the Ampere `LDGSTS` → `LDGDEPBAR` → `DEPBAR.LE SB0, N`
completion chain. This is an architecture capability, not a generic SASS rule:
`sm_86` exposes `AmpereLdgstsDepbarV1`, while `sm_120` returns a typed research
gap. The schedule join accepts exact unpredicated `LDGDEPBAR` commits and
`DEPBAR.LE SB0, <u32>` waits (decimal or hexadecimal), preserves the full wait
immediate, and rejects malformed, predicated, unknown, or layout-drifted forms.
The ordinary write-barrier latency is not applied to `LDGDEPBAR`'s SB0 protocol.

Each traced warp has one open group and a FIFO of committed groups. An
address-carrying `LDGSTS` adds its global-source completion to the open group;
`LDGDEPBAR` commits it; and wait-N requires the FIFO prefix older than the newest
N groups to be complete. Empty commits are immediately complete and consume no
sequence identity. Flat replay uses the existing global-flat completion,
constant-L1 replay uses the existing bypass/L2-hit completion, and shared-L2
replay receives the real L2-hit or DRAM response for every source sector.
Checked sequence/count/time updates and typed response identities keep failures
transactional. Scheduler readiness and skip-ahead include group completion
without a global cycle scan or an event per instruction, and equal-time replies
retain the engine's `(time, sequence)` order.

Cold protocol state lives in a parallel sparse sidecar owned by `SmCore`.
Non-async kernels keep the pre-increment 168-byte `WarpState`, a 56-byte
`IssueSlot`, an empty async sidecar, and a specialized readiness scan that omits
the wait FIFO walk. A later cold-function preflight experiment increased the
Embedding-flat median and hardware instruction count, so it was measured and
reverted rather than retained.

The final host profile also closed the older schedule-lookup deferral:
`BTreeMap::get` accounted for 6.79% of Embedding-flat samples because every
dynamic issue repeated the static PC lookup. Each `SmCore` now materializes the
small authoritative schedule map as a contiguous PC-ordered `(pc, slot)` table
and binary-searches it. This preserves the B-tree join and typed unknown-PC
diagnostics, adds no per-record field, and reduced the measured hardware count
from 7.271B to 6.666B instructions and 1.576B to 1.409B branches.

## sm_86 L2 pending-read coalescing (2026-08-15)

The admission increment exposed a specific lower-level concurrency error: event
reads treated a requested sector as absent until fill completion, but every read
of that already-pending sector minted another fill token and charged another DRAM
fetch. This preserved lookup-miss counting but inflated the six-workload cohort's
modeled DRAM traffic by as much as 20× once the unsupported L1 serialization was
removed.

### Model and event semantics

`sim-arch` now exposes `AllocationSectorMergeV1` only for `sm_86`; `sm_120`
returns a typed research gap. The L2 event API gained an opaque
allocation-generation/sector key and a coalesced transactional access surface.
A read mask is split into newly missing `fill_mask` sectors and matching
`pending_merge_mask` sectors. Both remain lookup misses, preserving L2 counters;
only the new mask mints a fill capability and consumes DRAM service. The older
distinct-fetch API remains as an explicit compatibility surface rather than
silently changing all L2 callers.

The shared system keeps a checked
`HashMap<L2PendingSectorKey, u64>` from each owned pending sector to its original
ready time. Registration is preflighted before the L2 plan commits; merged reads
must find every key; fill completion verifies the exact registered timestamp;
and both matching and stale/evicted completions remove their entries. Duplicate
registration, missing lookup, missing removal, timestamp mismatch, and a nonempty
map after queue drain are typed errors. Writes and atomics retain their previous
immediate-validation and fetch behavior: a write may supersede a pending valid
bit, but the original lower-level event and response still complete and retire
its key without resurrecting an evicted allocation.

A response is ready at the maximum of its ordinary L2-hit lower bound, every new
fetch's latency/bandwidth completion, and every merged sector's original ready
time. A mixed request can expose its new fill before a later joined response via
separate `L2Fill` and fill-less `MemResponse` events; equal-time fill+response
retains the single-event completion-before-delivery ordering. Focused tests cover
same-cycle and later-cycle merges, mixed masks, opaque generation identity,
stale eviction, write supersession, missing/colliding/removal state, rollback,
equal-time ordering, and the `sm_120` boundary.

## sm_86 LDGSTS payload-completion fanout (2026-08-15)

Pending-read coalescing corrected lower-level demand but left async groups visible as
soon as their last source sector returned. That omitted the independently observable
cost of delivering an effective `LDGSTS` payload into the async-copy completion
chain. This increment characterizes and models that cost without using any scored
workload's cycle label as an input.

### Independent payload characterization

The focused probe root is
`/var/tmp/gpu-simulator-async-fanout-probe-20260815-v1`. Static-unrolled kernels
issued 1, 2, 4, 8, 16, or 32 copies in each open group, followed by one commit and
`wait_group 0`. Compile-time unrolling removed the dynamic copy-loop branch and
index dependency; register count stayed fixed within each route/shape. Direct clock
samples and NCU profiles were collected synchronously in the foreground.

For cache-all `LDGSTS.E`, the stable high-fanout slopes were 62.69 effective
payload B/cycle for 32 lanes × 16 B, 62.66 B/cycle for 16 lanes × 16 B, and 64.12
B/cycle for 32 lanes × 8 B. The latter two forms carry the same 256-byte payload
with different active-lane/width shapes and converge to the same rate. For
`LDGSTS.E.BYPASS`, the corresponding 32-lane and 16-lane 16-byte forms converged
to 32.80 and 32.50 B/cycle. A separate cache-all source-stride comparison doubled
unique source sectors from 16 to 32 per 512-byte copy while retaining the payload;
the completion slope did not double. Effective active-lane payload, not the
already-modeled deduplicated source-sector count, is therefore the supported local
work variable.

The architecture values are 64 payload B/cycle for cache-all and 32 payload
B/cycle for bypass. The probes do not establish a finite queue depth or a
cross-warp arbitration policy, so neither was introduced.

### Architecture-local model and transactional boundaries

`sim-arch` exposes `LdgstsCompletionThroughput { 64, 32 }` only for `sm_86`;
`sm_120` returns the typed research gap
`sm_120 LDGSTS/TMA payload-completion throughput is not modeled`. The issue model
uses a fixed-point 64-unit service quantum: one unit per cache-all payload byte and
two units per bypass payload byte. Each copy contributes its effective payload
exactly once to its open group, independent of sector fanout. The conservative
group floor is:

`latest source completion + ceil(total committed-group delivery work / 64)`.

This deliberately does not claim overlap between early payload delivery and a
later source response, a shared global delivery queue, or measured cross-warp
arbitration. Source cache/L2/DRAM timing and traffic remain separate from this
completion tail.

The trace reader projects exact payload as the checked sum of each retained source
operand's width over effective lanes. Exact `u64` values live in a sparse warp-local
arena; replay narrows them through a typed `u64 -> u32` boundary before constructing
the dynamic token. Effective source presence is represented by nonzero payload,
while the static L1 policy remains explicit for predicated-off records. This keeps
`ValidatedMemoryInstruction` at 24 bytes, `AccessKind` at 16 bytes, and
`ReplayInst` at 24 bytes, with focused size tests preventing another silent
per-record widening.

Group count, accumulated work, and completion time are preflighted before mutation.
Response-side payload-floor overflow is rejected before response, cache, waiter,
or group state changes. Constant-L1 mode first uses a conservative batch-ready
bound; near a numeric boundary it replays the selected accesses on an exact shadow
L1 and publishes neither issue nor cache mutation unless source-ready plus payload
work fits. Focused tests cover route-local rates, sector-count independence,
once-per-copy accumulation, mismatches, multiplication/time overflow, response
rollback, constant-L1 retry rollback, and deterministic equal-time responses.
