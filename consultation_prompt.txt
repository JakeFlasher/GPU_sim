Chen Ding / locality literature findings to use, not overclaim
---------------------------------------------------------------
These are primary or official sources and should inform the plan:
* Chen Ding & Yutao Zhong, “Predicting whole-program locality through reuse
  distance analysis,” PLDI 2003, DOI
  https://doi.org/10.1145/780822.781159. The work uses approximate reuse
  distance (LRU stack distance), pattern recognition, and distance-based
  sampling to make whole-program locality predictions while controlling
  cost. It is not permission to fit this simulator to NCU rows.
* Dong Chen, PhD thesis advised by Chen Ding, “Program locality analysis
  based on reuse intervals,” University of Rochester (2019),
  http://hdl.handle.net/1802/35043. The abstract states that reuse intervals
  can be measured efficiently with dependence distance and can predict
  cache-line-granularity MRCs for complex loops/branches; it also models
  writebacks. Our dynamic GPU trace has no compiler dependence graph, so any
  reuse-interval use must be explicitly trace-derived and approximate.
* Liang Yuan, Chen Ding, Peter Denning, Yunquan Zhang, “A Measurement Theory
  of Locality,” https://arxiv.org/abs/1802.01254. It formalizes reuse time,
  reuse distance, working set, footprint, and miss ratio; an RD histogram
  directly gives the fully-associative LRU MRC, whereas reuse time alone does
  not generally determine reuse distance. Footprint differentiation gives
  bounds/approximations; finite traces and cold starts must be handled
  explicitly. Shared/interleaved caches need a defined reference stream.
* Chen Ding's official research pages:
  https://cs.rochester.edu/~cding/Research/ and
  https://cs.rochester.edu/people/faculty/ding_chen/index.html. They list
  reuse-distance prediction, locality phases, shared-cache metrics, spatial
  granularity, and write-locality work. The related “Fast Modeling L2 Cache
  Reuse Distance Histograms Using Combined Locality Information from Software
  Traces,” https://arxiv.org/abs/1907.05068, is relevant to multi-level L2
  approximation but must not be treated as validated for this GPU without
  evidence.

FOCUSED GATE FOLLOW-UP — IMPLEMENTATION SEAM
============================================
Before implementing the first observer, Gemini was consulted again through
the same read-only command. Its partial memo is `/tmp/gemini_reuse_gate.txt`.
The relevant finding is an explicit boundary, not a new hardware fact:

`TraceMetrics::observe_with_mask_presence_arch` is called while extraction
walks warp streams and cannot reconstruct a true inter-warp or cross-SM arrival
order. A physically meaningful L1 observer would need a passive hook in the
cycle-interleaved SM issue path; a physically meaningful L2 observer would
need the timestamp-ordered system event path. Therefore the first safe step
is a per-warp report-only reuse-interval census. It must not be promoted to
L1/L2 predictions because its curve is monotone. Lines within one memory
record share a logical tick, and their relative order is unavailable.

The implementation must label any RI curve an interval/sensitivity proxy:
exact fully-associative LRU MRC requires reuse distance; set-associative and
non-LRU behavior, SM120 geometry/hash/replacement, and right-censored final
intervals are not identified by this trace contract. Missing/empty spans are
explicit diagnostics. The executioner is authorized only to implement this
shadow phase, add invariant tests, validate it on full enabled-SM120 and SM86
replays with twelve workers, and stop before any active cache/timing change
unless a new Gemini consultation and evidence support promotion.

FOCUSED CORRECTION — RI IS NOT RD / MRC
=======================================
Gemini's complete correction memo is `/tmp/gemini_reuse_correction.txt`.
It supersedes any stronger interpretation of the earlier sketch: a timestamp
gap `Delta t` is reuse interval/time, while exact LRU reuse distance counts
distinct intervening items. Sector intervals do not prove sector residency
after tag eviction. The safe phase-1 output is therefore only a bounded RI
histogram and survival sensitivity proxy; it must not emit MRC hit rates or
feed them into cache/timing projections. A future exact sampled RD observer
would require deterministic SHARDS-style sampling plus an order-statistics or
Fenwick structure and a true issue/L2 arrival stream. Required go/no-go
invariants include reference conservation, coalescing idempotence,
`Delta t - 1 >= RD` for sampled witnesses, line/sector cardinality bounds,
and bit-identical timing when the observer is disabled.
